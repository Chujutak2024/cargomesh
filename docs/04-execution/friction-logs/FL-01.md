# FL-01 — Preview Vercel desalineado tras mover la app

- **Fecha:** 21 de septiembre de 2026 (Lima).
- **Estado:** abierto; borrador local, todavía no presentado como evidencia oficial del concurso.
- **Superficie:** previews de los PR [#81](https://github.com/Chujutak2024/cargomesh/pull/81), [#82](https://github.com/Chujutak2024/cargomesh/pull/82) y [#88](https://github.com/Chujutak2024/cargomesh/pull/88), posteriores al merge del PR #80 en `codex/v2-amazon-contracts`.

## Síntoma y reproducción

Los PR son mergeables según GitHub, pero el contexto `Vercel` falla. El PR #80 trasladó la aplicación Next.js desde `frontend/` a `cargomesh/`, mientras el proyecto Vercel mantiene `rootDirectory=frontend` y `productionBranch=main`. Crear un preview de una rama que ya contiene el traslado intenta construir el directorio anterior.

## Impacto y límite

No es evidencia de fallo de tests de dominio ni de que Alexa+ esté integrada. Sí impide usar el check de preview como gate verde de estos PR. `main` y el despliegue de producción no se cambiaron. No corregir un preview alterando silenciosamente el directorio raíz o la rama de producción: esa decisión afecta otros despliegues y requiere un plan separado.

## Resolución pendiente

1. El integrador acuerda una estrategia de preview V2 aislada y verifica qué directorio construye cada rama.
2. Se ejecutan los gates pertinentes de los PR y se adjuntan resultados al revisar su integración. En el worktree de PR #82 pasaron `pnpm typecheck`, `pnpm test:release`, `pnpm build` y `pnpm check:architecture` con dependencias instaladas offline desde el lockfile; esto verifica el código local, no el despliegue Vercel ni Alexa+ remota.
3. Solo entonces se reevalúa el check; registrar en este log la configuración y evidencia finales, sin afirmar que el incidente está resuelto antes de comprobarlo.

**Evidencia inicial:** estado `UNSTABLE` y contexto `Vercel: FAILURE` en los PR #81/#82 al 21 de septiembre de 2026 (Lima); `Vercel Preview Comments` aparece exitoso, pero no sustituye el build.

**Seguimiento 23 de septiembre de 2026:** PR #88 reproduce el mismo límite: GitHub muestra `Vercel Preview Comments` exitoso y un deployment Vercel en `Error`, mientras `pnpm build` pasa localmente desde `cargomesh/`. La rama contiene `cargomesh/` y no `frontend/`; `origin/main` todavía contiene `frontend/`. No se modificó la configuración del proyecto Vercel desde HAC-24.
