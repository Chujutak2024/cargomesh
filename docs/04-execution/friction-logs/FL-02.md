# FL-02 — Esquema Supabase remoto detrás del contrato ROAD V2

- **Fecha:** 23 de septiembre de 2026 (Lima).
- **Estado:** resuelto para el esquema ROAD V2 el 23 de septiembre de 2026; faltan escenarios/capacidades de aplicación y validación de gate.
- **Superficie:** proyecto Supabase `cargomesh` (`tokvzfrefwqobzqgbfoj`) frente a migraciones del repositorio.

## Hallazgo reproducible

La consulta de solo lectura `list_migrations` muestra como última migración remota `20260902213000_c_restrict_freight_request_writes`. En Git existen además `20260918120000_c_draft_creation_idempotency.sql` y `20260922053512_v2_road_facilities_services.sql`. `list_tables(public, verbose=true)` confirma que el remoto aún no contiene `facilities`, `carrier_depots`, `service_areas` ni `service_lanes`. El export de esquema compartido por el usuario tampoco las incluye.

## Impacto y límite

El contrato de HAC-21 y sus pruebas locales no equivalen a aplicación en el proyecto remoto. Una revisión del modelo de dominio basada solo en el remoto perdería sedes, áreas, lanes, evidencia y vigencia V2; una basada solo en Git afirmaría prematuramente que están disponibles en ese entorno. Las columnas legacy de `carrier_services`/`vehicles` no prueban cobertura ni capacidad V2 por fecha. No se infiere que haya fallo de migración: puede ser una separación deliberada de entornos/gates.

## Seguimiento

1. Se confirmó el proyecto enlazado `cargomesh` (`tokvzfrefwqobzqgbfoj`). `supabase db push --linked --dry-run --skip-vault` enumeró exclusivamente las dos migraciones pendientes y ningún seed/rol.
2. Con autorización del usuario, `supabase db push --linked --skip-vault --yes` aplicó `20260918120000_c_draft_creation_idempotency.sql` y `20260922053512_v2_road_facilities_services.sql`. Ambas aparecen ahora en el historial remoto.
3. Consulta posterior: existen `facilities`, `carrier_depots`, `service_areas`, `service_lanes`; las cuatro tienen RLS activa y políticas (3 para `facilities`, 1 para cada una de las otras). Las cuatro columnas nuevas de `freight_requests` están presentes, así como dos FK hacia facilities, el índice de idempotencia y el trigger `guard_freight_creation_receipt`. Las cuatro tablas ROAD tienen cero filas: no se insertaron datos de demo.
4. El asesor de seguridad no reportó fallos nuevos de esas tablas. Conserva una advertencia ajena a estas migraciones: protección de contraseñas filtradas desactivada en Supabase Auth; evaluar su activación en configuración de proyecto ([guía](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)).
5. El [modelo UML](../../v2-amazon/DOMAIN_UML_MODEL.md) debe actualizar su etiqueta `as-is` remoto cuando se revise para aprobación. El esquema remoto actualizado no prueba por sí solo discovery, capacidad por fecha ni Alexa+ live.

**Límite de la intervención:** solo migraciones estructurales indicadas; ningún seed, fila de cliente, cambio de Vault, despliegue Web, `main` ni Linear.
