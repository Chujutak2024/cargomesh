# Domain models and schema references

These are engineering design inputs and generated mappings, not a certification that every class/method is implemented or deployed. Use the [current architecture](../../ARCHITECTURE.md), [API](../../API.md) and [status](../../STATUS.md) for the running product.

- [Full derived ERD](FULL_MODEL_DER.md): generated by `scripts/build-v2-full-der.py`; use `--check` to verify it.
- [Physical design](FULL_MODEL_PHYSICAL_DESIGN.json), [current attributes](FULL_MODEL_CURRENT_ATTRIBUTES.json), [relations](FULL_MODEL_CURRENT_RELATIONS.json) and [identity mapping](FULL_MODEL_CURRENT_IDENTITY.json): machine-readable inputs/decisions.
- [UML inventory](FULL_MODEL_UML_INVENTORY.json) and [targets](FULL_MODEL_TARGETS.json): source inventory checked by `scripts/check-v2-full-model.py`.
- [Reviewed diagram input](../diagrams/review-2026-09-24/07-complete-classes-sprint2-reviewed.drawio), [attribute dictionary](../delivery/HAC27_UML_ATTRIBUTE_DICTIONARY_2026-10-02.md) and [schema/API contract](../delivery/SPRINT2_HAC27_CLASS_DB_API_CONTRACT.md): retained because QA consumes these inputs.

Other conceptual/design reviews in this directory are supporting design material; they do not override the [domain contracts](../contracts/README.md). Verify proposed changes against source, SQL and tests rather than treating a design status or old test count as current evidence.
