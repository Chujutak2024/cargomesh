## Open and use

Use an authenticated Client membership and open `/clients/facilities`. Select an own
persisted Facility. The **3D reference** section below the directory offers 15 existing
architectures. Selecting previews the illustration; **Save model** explicitly persists
it. Select **No model selected** and save to clear it. An unassigned Facility has no
inferred model. Existing address/hours/function records are never changed by this action.
OWNERS and SUPERVISORS can change it; REQUESTERS read it. The renderer is reference-only:
no invented vehicles, activity, stock, capacity, coverage or coordinates.

Camera/interior state lives above Facility selection and editor revisions, keyed by
organization/Facility/model. Switching back restores the same reference coordinator.
Existing WebGL fallback leaves the saved details and selector usable.

## API and persistence

- `GET /api/v2/facilities/:id/visual-reference`: authorized own Facility, including
  version0/null model when unassigned. No row is created by reading.
- `POST` same route: `{expectedVersion, templateId}` with `Idempotency-Key` UUID.
  Explicit save; native cookie origin guard, bearer identity boundary, private/no-store
  responses. Identity comes from active Auth/member/organization, never browser input.
- `public.facility_visual_references`: Facility PK, organization composite FK, model,
  independent positive version and timestamp. RLS reads; no direct Data API writes.
- Private RPC validates actual actor/role/tenant, model catalogue, SHA-256 idempotency
  and optimistic version. Locks serialize first-write races. Clear retains a null model
  row/version rather than erasing concurrency history. Private receipts are inaccessible.
- The data-only catalogue is shared under `src/shared/facility-visual-catalog.ts`;
  existing `depot-templates.ts` re-exports it. Geometry, identities and catalogue count
  remain unchanged. UI-layer imports do not enter the backend.
