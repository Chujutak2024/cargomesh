# FL-03 — puerto del replay local HAC-29 reservado por Windows

- **Fecha:** 27 de septiembre de 2026 (Lima).
- **Estado:** abierto para portabilidad local; CI de PR #90 verde.
- **Dueño de seguimiento:** HAC-29 (Jean Paul); revisor HAC-12 (Cristhian).
- **Superficie:** `supabase-v2/gate.py v2`, proyecto Docker de referencia `hac29-v1-reference`.

## Hallazgo reproducible

En este host, `python supabase-v2/gate.py v2 --evidence-dir <temporal>` termina antes del reset V2 porque Docker no puede enlazar el puerto `59322` del replay V1. `netsh int ipv4 show excludedportrange protocol=tcp` muestra el intervalo reservado `59241–59340`. No es un error de migración ni una consulta al Supabase alojado.

## Alcance y verificación alternativa

Los tres jobs GitHub Actions del [PR #90](https://github.com/Chujutak2024/cargomesh/pull/90) pasaron. En este host se ejecutaron por separado: reset local V2 limpio, ocho categorías y cero filas de negocio/Auth, seed/verify del escenario, 73 pgTAP de HAC-29 y cleanup con backup previo. Después, en un checkout de validación desacoplado, el reset HAC-29 → HAC-12, ambos escenarios, 90 pgTAP y smoke HTTP real pasaron. Esto **no** equivale a ejecutar el `gate.py v2` completo en Windows ni acredita la publicación de HAC-12.

## Seguimiento

HAC-29 debe permitir seleccionar puertos libres para los proyectos de replay sin relajar la separación de contenedores ni el gate de CI; luego repetir el comando completo en Windows. Mientras tanto, conservar este resultado como `BLOCKED local / PASS CI`, no como gate local completo. No se modificaron puertos del sistema, ramas remotas ni Supabase alojado.
