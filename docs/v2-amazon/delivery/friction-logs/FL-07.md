# FL-07 — Alexa+ CLI guide is gated for hackathon participants

- **Date:** 5 October 2026 (America/Lima).
- **Status:** resolved with a supported submission path; no escalation to Amazon required.
- **Surface:** Alexa+ primary track, HAC-38 self-hosted MCP adapter.

## Friction

The public Alexa+ environment setup guide instructs developers to create an IAM user and assume Amazon's `AddOn3PDeveloperToolsRead` role in order to install the private Alexa AI CLI. CargoMesh followed that configuration with a dedicated least-privilege IAM user. Its base credentials were valid, but `aws sts get-caller-identity --profile alexa-ai` consistently returned `AccessDenied` for the Amazon-owned role.

The hackathon FAQ and a confirmed organizer response clarify the reason: Alexa+ Category SDK, MCP Toolkit, CLI, and Web Simulator are preview tools limited to selected partners. Hackathon participants cannot apply for or be granted access, including through the documented role. The setup guide does not surface that limitation prominently enough for hackathon participants.

## Evidence

- FAQ: <https://amazonappdev2026.devpost.com/details/faqs>
- Organizer response: <https://amazonappdev2026.devpost.com/forum_topics/45262-is-the-alexa-mcp-toolkit-alexa-ai-cli-available-to-hackathon-participants>
- Official rules: <https://amazonappdev2026.devpost.com/rules>

## Workaround and recommendation

The official rules accept a self-hosted Streamable HTTP MCP server implementing protocol version `2025-11-25` or later, or a self-built Alexa+ simulation. CargoMesh will use its V2 MCP server and Web conversation as those artifacts and will label them accurately. No further IAM permissions, access keys, CLI installation, or Alexa+ add-on claims are required.

**Suggested improvement:** Put the partner-only restriction and the hackathon-supported self-hosted MCP/simulation path at the top of the public Alexa+ environment setup guide.
